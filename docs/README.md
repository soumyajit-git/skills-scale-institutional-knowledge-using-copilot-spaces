# OctoAcme Project Management Docs

This folder is the central hub for OctoAcme's project management processes. It provides a concise summary of our approach and links to the canonical process documents used to initiate, plan, execute, release, and improve work. These docs are designed to accelerate onboarding, reduce single-person knowledge risk, and give the delivery team a consistent framework for decision-making, communication, and quality.

OctoAcme follows a customer-first, iterative delivery model with a clear lifecycle: Initiation → Planning → Execution → Release → Close & Retrospective. Projects start with a one‑pager to confirm the problem, stakeholders, and success metrics; move into planning where work is broken into shippable backlog items with acceptance criteria; and execute using a project board and short iterations. Pull requests are kept small, include acceptance criteria, and require automated CI checks and at least one approval before merging.

Roles and clear ownership are emphasized: Product Managers define outcomes and success metrics; Project Managers coordinate delivery, schedules, and risks; Developers build and test; QA validates acceptance criteria; and Stakeholders provide approvals and input. This role clarity helps reduce handoffs and ensures each artifact (one‑pager, backlog, DoD, risk register) has a named owner and expectations for quality.

Communication and quality practices are embedded in the process: daily standups to surface progress and blockers, weekly delivery syncs for risks and status, regular demos, and monthly stakeholder updates as needed. Quality assurance includes unit and integration tests, end‑to‑end smoke tests for critical flows, CI-based linting and security scanning, and manual QA for feature acceptance when required. Retrospectives capture action items and feed improvements back into the backlog.
